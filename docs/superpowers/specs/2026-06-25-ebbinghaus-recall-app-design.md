# 艾宾浩斯背诵小软件 设计文档

## 概述

一个供个人自用的桌面背诵辅助软件。用户每天将背诵内容记录到软件中，软件依据艾宾浩斯遗忘曲线在到期日提醒复习，用户复习后打卡，软件自动安排下一次复习日期。完成完整复习周期后，软件确认用户是否真正掌握，并据此归档或继续提醒。整体逻辑参考"不背单词"App 的复习机制。

## 目标与非目标

**目标**
- 记录每日背诵内容（标题 + 正文）
- 按艾宾浩斯曲线自动排程并提醒复习
- 复习打卡后自动推进下一次复习日期
- 漏打卡时持续提醒，从实际打卡日重算下次日期
- 完成周期后确认掌握程度，按程度分流处理

**非目标**
- 不做云同步、多设备共享
- 不做后台常驻 / 系统通知（打开软件时查看今日待复习即可）
- 不做账号系统、多用户支持
- 不做内容分享、社区功能

## 技术栈

- **语言**：Python 3
- **GUI**：CustomTkinter（现代外观的 Tkinter 封装）
- **存储**：SQLite（Python 内置 `sqlite3` 模块，零额外依赖）
- **平台**：Windows 桌面应用

## 项目结构

```
艾宾浩斯小软件/
├── main.py              # 程序入口，启动 GUI
├── scheduler.py         # 艾宾浩斯复习调度引擎（核心逻辑，纯逻辑无 UI 依赖）
├── database.py          # SQLite 数据层（建表、增删改查）
├── ui/
│   ├── main_window.py   # 主窗口（三标签页：今日待复习 / 全部条目 / 已掌握）
│   ├── review_panel.py  # 复习交互面板（展开正文、打卡、掌握确认）
│   └── add_dialog.py    # 新建背诵对话框
└── data/
    └── ebbinghaus.db    # SQLite 数据库文件（运行时自动创建）
```

## 三层架构

1. **数据层 `database.py`**：封装所有 SQLite 操作。提供"查今日到期条目""记录一次打卡""新建条目"等方法，对上层屏蔽 SQL 细节。首次运行自动建库建表。

2. **调度引擎 `scheduler.py`**：纯逻辑层，不依赖 UI。负责：根据当前阶段计算下次复习日期、判断某条目今天是否到期、处理打卡后状态推进、处理掌握确认后的周期切换。可脱离 GUI 独立测试。

3. **UI 层 `ui/`**：CustomTkinter 界面，只负责展示和接收操作，所有复习逻辑调用 `scheduler`。

## 数据模型

### 表 `items`（背诵条目）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INTEGER PK | 自增主键 |
| `title` | TEXT | 标题 |
| `content` | TEXT | 正文 |
| `created_date` | TEXT | 创建日期（ISO 格式 `YYYY-MM-DD`） |
| `status` | TEXT | 状态：`learning`（学习中）/ `pending_mastery`（待确认掌握）/ `mastered`（已掌握） |
| `current_stage` | INTEGER | 当前所处复习阶段序号（见下方"复习阶段"） |
| `next_review_date` | TEXT | 下次复习日期（ISO 格式） |
| `cycle_start_date` | TEXT | 当前周期起始日期（用于计算阶段间隔；重走周期时更新） |
| `cycle_type` | TEXT | 当前周期类型：`full`（完整周期）/ `short`（短周期再确认）。决定使用哪张间隔表 |

### 表 `review_logs`（复习记录）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INTEGER PK | 自增主键 |
| `item_id` | INTEGER FK | 关联 `items.id` |
| `review_date` | TEXT | 复习日期（ISO 格式） |
| `stage_completed` | INTEGER | 本次完成的阶段序号 |
| `result` | TEXT | 结果：`done`（正常打卡）/ `mastered`（确认掌握）/ `fuzzy`（模糊）/ `forgotten`（完全未掌握） |

## 复习调度逻辑

### 复习阶段

完整艾宾浩斯周期共 6 个阶段，间隔天数从周期起始日算起：

| 阶段序号 | 间隔天数 |
|----------|----------|
| 1 | 1 |
| 2 | 2 |
| 3 | 4 |
| 4 | 7 |
| 5 | 15 |
| 6 | 30 |

模糊再确认短周期共 3 个阶段：

| 阶段序号 | 间隔天数 |
|----------|----------|
| 1 | 1 |
| 2 | 3 |
| 3 | 7 |

### 状态流转

```
新建条目（status=learning, current_stage=1, cycle_type=full, cycle_start_date=今天, next_review_date=今天+1天）
  │
  ▼
学习中：按完整周期阶段 1→2→3→4→5→6 依次复习
  │
  │ 每次到期未打卡 → 持续每天出现在"今日待复习"中
  │ 打卡后 → next_review_date = 打卡日 + 下一阶段间隔天数
  │          current_stage 推进到下一阶段
  │
  ▼ 完成阶段 6（第30天）打卡
  │
待确认掌握（status=pending_mastery）
  │ 软件弹窗询问掌握程度
  │
  ├─ 已掌握 → status=mastered，归档，不再提醒
  │
  ├─ 模糊 → 进入短周期再确认
  │          status=learning, current_stage=1, cycle_type=short, cycle_start_date=今天
  │          next_review_date=今天+1天
  │          （后续按 1/3/7 天短周期复习，每次到期再问掌握程度）
  │          ├─ 仍模糊 → 重置短周期，继续 1/3/7 天
  │          ├─ 已掌握 → 归档
  │          └─ 完全忘了 → 重走完整周期（cycle_type=full, current_stage=1, cycle_start_date=今天, 按完整周期排程）
  │
  └─ 完全未掌握 → 重走完整周期
                  status=learning, current_stage=1, cycle_type=full, cycle_start_date=今天
                  next_review_date=今天+1天
```

### 关键规则

1. **漏打卡处理**：条目到期日未打卡，该条目每天持续出现在"今日待复习"列表中。打卡后，下一次复习日期从**实际打卡日**重新计算（而非原计划日期）。

2. **阶段推进**：打卡时，`current_stage` 推进到下一阶段，`next_review_date = 打卡日 + 下一阶段间隔天数`。若当前已是最后阶段，则进入"待确认掌握"状态。

3. **今日到期判断**：`next_review_date <= 今天` 的条目视为今日待复习。

4. **周期类型标记**：`cycle_type` 字段明确记录条目当前处于 `full`（完整周期）还是 `short`（短周期再确认）。调度引擎根据此字段选择对应的间隔表。进入短周期时设为 `short`；重走完整周期时设为 `full`。

## 界面设计

### 主窗口（三标签页 + 顶部按钮）

**顶部**：`新建背诵` 按钮

**标签页 1：今日待复习**
- 列表展示今天到期的所有条目（`status=learning` 或 `pending_mastery` 且 `next_review_date <= 今天`）
- 每条显示：标题、距上次复习天数、当前阶段
- 点击条目展开正文
- `learning` 状态条目：显示`打卡`按钮
- `pending_mastery` 状态条目：显示`确认掌握`按钮，点击后弹窗询问掌握程度（已掌握 / 模糊 / 完全未掌握）

**标签页 2：全部条目**
- 列表展示所有 `status=learning` 或 `pending_mastery` 的条目
- 每条显示：标题、创建日期、当前阶段、下次复习日期
- 支持点击查看详情

**标签页 3：已掌握**
- 列表展示所有 `status=mastered` 的条目
- 可点击查看正文和复习历史

### 新建背诵对话框

- 标题输入框（单行）
- 正文输入框（多行）
- `保存` / `取消` 按钮
- 保存后：条目创建，立即进入学习中状态，首次复习日期为明天（阶段 1，间隔 1 天）

### 掌握确认弹窗

完成第 30 天复习后弹出：
- 显示条目标题和正文
- 三个按钮：`已掌握` / `有点模糊` / `完全没记住`
- 选择后按状态流转逻辑处理

## 错误处理

- 数据库文件损坏：捕获 `sqlite3.DatabaseError`，提示用户并备份原文件后重建
- 日期解析失败：以创建日期兜底，记录警告日志
- GUI 操作异常：捕获并弹窗提示，不崩溃

## 测试策略

- **调度引擎单元测试**（重点）：
  - 新建条目的初始排程正确
  - 各阶段打卡后 `next_review_date` 计算正确
  - 漏打卡后持续到期
  - 打卡后从打卡日重算
  - 完成30天周期进入 `pending_mastery`
  - 三种掌握确认结果的状态流转正确
  - 短周期再确认的排程正确
  - 短周期内再次模糊/掌握/遗忘的流转正确
- **数据层测试**：建表、增删改查、外键约束
- **GUI 手动测试**：新建、打卡、确认掌握的完整流程

## 依赖
